## Ограничение WARP при подборе

Первые экспериментальные проверки выполнялись параллельно. Для одного профиля WireGuard такая методика может давать ложные таймауты: один ключ обозначает одного пира, а его адрес меняется при roaming. Поэтому итоговый подбор с WARP проверяет серверы последовательно; без WARP — по четыре одновременно. Это вывод о возможном источнике нестабильности, а не доказательство причины каждого таймаута. См. [описание roaming WireGuard](https://www.wireguard.com/known-limitations/).

WARP передаёт UDP через выбранный VPN. Успешный обычный HTTPS через сервер не доказывает работоспособность этой цепочки: сервер должен передавать UDP WireGuard, а Google должен принимать получившийся выход. См. [ограничения протокола WireGuard](https://www.wireguard.com/known-limitations/).

## Проверка на реальной сети

В отдельном экземпляре Xray обычную страницу Flow без WARP открыли «Австрия N1 (Gemini)» и «Швейцария N1 (Gemini)». «Франция N1 (Gemini)» при этой проверке дала ошибку TLS. Пометка Gemini сама по себе не гарантирует результат.

Через текущий WARP Flow также отдал обычную страницу. В браузере открылась страница `/about`, а кнопка создания привела ко входу Google. Проверка выполнена без входа в аккаунт: работоспособность генерации и ограничения конкретного аккаунта не подтверждены. Автоматический подбор проверяет сетевой доступ к обычной странице Flow.

Результаты проверки отдельных серверов находятся локально в `scratch/flow_live_results.json`. Расширенные параллельные WARP-замеры находятся в `scratch/flow_all_warp_results.json`; их отрицательные результаты предварительные из-за описанного ограничения профиля.

## Дополнительная проверка после входа

Первоначальная проверка HTML до входа оказалась недостаточной: пользователь сообщил, что Gemini открывается, а Flow после авторизации показывает `unsupported-country`. Поэтому результаты обычной страницы выше подтверждают только её сетевую доступность и не подтверждают доступ к рабочему Flow.

Запущен отдельный профиль установленного Google Chrome через активный `warp-http-in` на порту 10811. Весь его веб-трафик, включая вход Google и служебные запросы Flow, использует этот прокси; QUIC отключён, непроксируемый WebRTC UDP отключён. Профиль Chrome: `%LOCALAPPDATA%\GibVPN\FlowChromeWARP`. Существующие приложения, VPN-процессы и маршруты Windows не перезапускались.

Соединения сетевого процесса Chrome с портом WARP-прокси подтверждены. После входа пользователь сначала сообщил о региональной заглушке, затем подтвердил: «заработало». Это подтверждение доступа к самому Flow в данном отдельном окне. Точная причина отличия от исходного браузера пока не установлена; нельзя утверждать, что виноват конкретный отсутствующий домен.

Для повторного открытия этого профиля используйте `FLOW_WARP_CHROME.cmd`. Скрипт получает порт WARP из текущей конфигурации GibVPN; он не перезапускает VPN и не меняет настройки обычного браузера. Открытие страницы до входа по-прежнему не следует считать достаточной проверкой режима «ИИ».
